# Mío — семейный мессенджер

Простой приватный чат: регистрация, личные сообщения в реальном времени, отправка фото. Работает как обычный сайт — родным просто нужна ссылка, VPN не требуется (это же не Telegram, а твой собственный сервер).

## Что умеет уже сейчас
- Регистрация и вход по логину/паролю
- Личные чаты 1-на-1
- Сообщения в реальном времени (без обновления страницы)
- Индикатор "печатает..."
- Отправка фото
- Отправка своей геолокации — спрятана в меню "➕" рядом с полем ввода, отправляется только по явному нажатию тем, чья это геолокация
- **Аудиозвонки** между двумя людьми в личном чате — с гудками, таймаутом 10 сек и отметкой "📵 Пропущенный звонок" в чате, если не взяли трубку
- **Push-уведомления** о новых сообщениях, даже когда вкладка/приложение закрыты
- **Отправка видео** и **голосовых сообщений** (🎤 рядом с полем ввода)
- **Профиль собеседника** — тап на имя/аватар в шапке чата открывает карточку профиля
- **Профиль в стиле Telegram** — крупная аватарка, поля "О себе", телефон, дата рождения (видны собеседникам, без верификации по SMS — это платная штука, для семьи не нужна)
- **Истории на 24 часа** — сворачиваемая лента (потяни ручку под шапкой чатов, чтобы открыть). Публиковать может только Premium-аккаунт (⭐ или любой другой выбранный эмодзи), смотреть — все, у кого есть общий чат с автором
- **Отправка файлов** — документы, таблицы, архивы, любые форматы — через 📄 в меню вложений, с иконкой по типу и размером
- **Значок верификации ✅** — только твой аккаунт (задаётся переменной `ADMIN_USERNAME`) может выдавать другим (и себе) синюю "печать" с галочкой; тап по значку показывает подсказку ("Официальный аккаунт разработчика" — для тебя, "Этот аккаунт верифицирован" — для остальных)
- **Premium-подписка ⭐** — та же логика: только ты выдаёшь фиолетовую звёздочку с лёгкой анимацией, появляется справа от галочки верификации
- **Профиль — отдельная полноэкранная страница**, а не всплывающее окошко (и свой, и чужой)
- **Удаление чата целиком** — пропадает из списка у обеих сторон вместе с историей (не путать с "Очистить историю", которая просто стирает переписку, но оставляет чат в списке)
- **Тёмная тема** и выбор цвета интерфейса
- **Групповые чаты** — создание группы с несколькими участниками, просмотр списка участников тапом на название группы
- **Групповые чаты** — создание, своя фотка и название группы, добавление/удаление участников, выход из группы
- **Статус "в сети" / "был(а) недавно"** — виден в шапке чата и в карточке профиля
- **Ответы на сообщения** — цитирование (кнопка ↩ у каждого сообщения)
- **Реакции** — тап по сообщению открывает меню с эмодзи-реакциями и действиями
- **Редактирование и удаление** своих сообщений — через тап-меню на сообщении
- **Свайп для ответа** (влево по сообщению) и **свайп назад к списку чатов** (вправо, на телефоне)
- **Отключение уведомлений** для конкретного чата — через "⋮" в шапке чата
- **Поиск по переписке** — там же, через "⋮"
- **Разделители дат** — "Сегодня", "Вчера" и даты между сообщениями разных дней
- **Свой фон чата** — цветные пресеты или своя фотка, у каждого чата свой (хранится на устройстве)
- **Свои темы оформления** — любой цвет через колесо + сохранение нескольких своих тем с именами
- **Пересылка сообщений** в другие чаты — через тап-меню на сообщении
- **Закрепление сообщения** в чате — баннер 📌 сверху, тап переносит к сообщению
- **Упоминания @username** в группах — с автодополнением при вводе "@", подсвечиваются в тексте, пробивают отключённые уведомления (как в Telegram)
- **Устанавливается как приложение** — через "Добавить на экран «Домой»" превращается в отдельную иконку без адресной строки браузера
- **Статусы сообщений** — одна галочка = отправлено, две синие = прочитано
- История переписки

- Подарки
- Пароль/отпечаток на вход в приложение

## Как установить как приложение

**Android (Chrome):** откроется баннер "Добавить на главный экран" сам, либо через меню (⋮) → "Установить приложение".
**iPhone (Safari):** кнопка "Поделиться" (квадрат со стрелкой) → "На экран «Домой»". После этого запускай именно с этой иконки, а не через Safari — так и push-уведомления будут работать нормально, и выглядеть будет как настоящее приложение (без адресной строки).

## Надёжные звонки (TURN-сервер)

Раньше звонки работали "как повезёт" — использовался только STUN-сервер, который не пробивает многие мобильные сети и строгие роутеры (отсюда "не слышно звука"/"звонок не идёт"). Теперь можно подключить настоящий TURN-сервер — он передаёт голос через посредника, если напрямую соединиться не получается.

### Как подключить (бесплатно, с телефона)

1. Зайди на [metered.ca](https://www.metered.ca) → зарегистрируйся, выбери Free план, создай проект.
2. В разделе **TURN Server** найди свою запись в таблице **TURN Credentials** и нажми жёлтую кнопку **"Show ICE Servers Array"**.
3. Скопируй весь появившийся текст (это JSON-массив вида `[{"urls": "stun:...", ...}, ...]`).
4. В Render → Environment добавь переменную:
   - `METERED_ICE_SERVERS_JSON` = вставь то, что скопировал (целиком, в одну строку)
5. Сохрани — Render передеплоит сервис.

Без этих переменных звонки продолжат работать через STUN (как раньше — иногда нормально, иногда без звука). С ними — счёт вероятности успешного соединения гораздо выше, особенно на мобильном интернете.

### Про "не в сети"

Если собеседник видит браузер с мессенджером не в фоне (заблокирован телефон / свёрнута вкладка), браузер отключает живое соединение — в этот момент дозвониться до него технически невозможно (это ограничение любого браузерного, а не нативного приложения). Теперь в таком случае звонок автоматически отмечается как **пропущенный** прямо в переписке — собеседник увидит его, когда откроет чат, и получит push-уведомление, если оно настроено.

## Важно про Push-уведомления

Push-уведомления используют пару ключей (VAPID), которые должны оставаться одинаковыми всегда — иначе у всех "слетают" подписки при каждой пересборке (это и произошло раньше). Теперь, если не задать `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` вручную, сервер сгенерирует их сам и **выведет в логи Render при старте** — зайди в Render → Logs сразу после первого деплоя с этим обновлением, найди строки, начинающиеся на `VAPID_PUBLIC_KEY=` и `VAPID_PRIVATE_KEY=`, скопируй оба значения и добавь их как переменные окружения в Render → Environment. Дальше это нужно сделать только один раз.

## Постоянное хранилище файлов (Cloudinary)

Фото, видео и голосовые сообщения теперь хранятся не на диске Render (он временный), а в Cloudinary — облаке для медиафайлов с щедрым бесплатным лимитом (25 "кредитов" в месяц, где 1 кредит ≈ 1 ГБ хранения или трафика — для семейного чата с запасом хватит надолго).

### Как подключить (с телефона)

1. Зайди на [cloudinary.com](https://cloudinary.com) → зарегистрируйся бесплатно.
2. На главной странице личного кабинета (Dashboard) найди три значения: **Cloud Name**, **API Key**, **API Secret**.
3. В Render → твой Web Service → **Environment** → добавь три переменные:
   - `CLOUDINARY_CLOUD_NAME`
   - `CLOUDINARY_API_KEY`
   - `CLOUDINARY_API_SECRET`
4. Сохрани — Render передеплоит сервис.

Пока эти переменные не заданы, загрузка файлов будет выдавать ошибку — старые фото, отправленные до этого шага, всё равно останутся на прежнем нестабильном хранилище и могут пропасть при следующей пересборке.

## Важные технические нюансы

**Звонки.** Используется прямое соединение между браузерами (WebRTC) без промежуточного сервера для голоса — это быстрее и приватнее. Ограничение: в редких случаях (если у кого-то очень строгий Wi-Fi/роутер) звонок может не пробиться. Для обычного домашнего интернета всё работает. Если столкнётесь с этим — скажите, добавим TURN-сервер (решает проблему, но требует отдельного недорогого сервиса).

**Push-уведомления на iPhone.** Apple разрешает push-уведомления в браузере, только если сайт добавлен на домашний экран как приложение ("Поделиться" → "На экран «Домой»"). Из обычной вкладки Safari уведомления работать не будут — это ограничение iOS, а не мессенджера. На Android и компьютере работает из обычного браузера.

**И звонки, и геолокация, и push требуют HTTPS** (обычный `http://` браузер не пускает к микрофону/геолокации из соображений безопасности). Render выдаёт `https://` автоматически, так что после деплоя всё должно работать из коробки.

## Запуск без ПК и без своего сервера (полностью с телефона)

Всё делается через два бесплатных сайта: **GitHub** (хранит код) и **Render.com** (запускает его как сайт). Ничего устанавливать на телефон не нужно — всё происходит в браузере.

### Шаг 1. Разархивируй проект на телефоне
Открой скачанный `family-messenger.zip` в файловом менеджере телефона (у Android и iPhone есть встроенная функция "Извлечь"/"Распаковать") — получится папка `family-messenger` с файлами внутри.

### Шаг 2. Залей код на GitHub
1. Зайди на [github.com](https://github.com) с телефона, зарегистрируйся (бесплатно).
2. Нажми **New repository** → назови, например, `family-messenger` → **Create repository**.
3. На странице репозитория нажми **Add file → Upload files**.
4. Через файловый менеджер выбери все файлы и папки из распакованной `family-messenger` (кроме `node_modules`, если он вдруг появится — его быть не должно) и загрузи. Если браузер не даёт выбрать сразу папку — загружай файлы по одному, сохраняя те же названия и пути (например `public/index.html`).
5. Нажми **Commit changes**.

### Шаг 3. Разверни на Render
1. Зайди на [render.com](https://render.com), зарегистрируйся через свой GitHub-аккаунт (это свяжет аккаунты автоматически) — карта не требуется.
2. Нажми **New → Web Service**, выбери репозиторий `family-messenger`.
3. Заполни:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. В разделе **Environment Variables** добавь `JWT_SECRET` (длинная случайная строка, минимум 32 символа; сгенерируй командой из файла `.env.example`) и `INVITE_CODE` (код приглашения для регистрации). **Без `JWT_SECRET` сервер не запустится.** Не используй примеры из интернета: секрет должен быть только твоим.
5. Нажми **Create Web Service** — через пару минут Render выдаст тебе ссылку вида `https://family-messenger.onrender.com`. Это и есть адрес мессенджера — скидываешь его родным, и все заходят с телефона или компьютера через браузер, без VPN.

**Важные нюансы бесплатного тарифа Render:**
- Сервис "засыпает" после 15 минут без обращений и "просыпается" ~30–60 секунд при следующем сообщении — для семейного чата это не критично, просто первое сообщение после паузы придёт с задержкой.
- На бесплатном тарифе файловое хранилище не гарантированно постоянное: при пересборке проекта (например, если ты обновишь код) сообщения и фото из базы `messenger.db` могут очиститься. Для тестирования и знакомства с приложением это нормально. Когда решишь, что мессенджер прижился — скажи, подключим постоянную базу (Render предлагает бесплатный Postgres на 90 дней, дальше недорого) и данные перестанут теряться.

Если что-то на любом из шагов не получится — пришли скриншот, разберём вместе.

## Постоянное хранилище данных (Turso)

Раньше все чаты и пользователи хранились в файле на диске Render, который иногда сбрасывался при пересборке. Теперь база вынесена в Turso — облачную SQLite-совместимую базу с щедрым бесплатным лимитом, данные больше не пропадают.

**Важно:** это решает проблему для текстовых данных (пользователи, чаты, сообщения). Сами присланные **фото** пока всё ещё хранятся на диске Render и могут теряться при пересборке — это отдельная задача на будущее.

### Как подключить (с телефона, без установки чего-либо)

1. Зайди на [turso.tech](https://turso.tech) → зарегистрируйся (через GitHub или почту).
2. В личном кабинете нажми **Create Database** (может называться "New Database").
3. Дай базе любое имя, выбери ближайший регион (Europe/Frankfurt подойдёт).
4. Открой созданную базу → вкладка вроде **Connect** или **Overview** — там будет **Database URL** (начинается с `libsql://...`) — скопируй его.
5. Там же должна быть кнопка **Create Token** (или в разделе Settings/Tokens) — создай токен и скопируй его. Он показывается только один раз, сразу сохрани.
6. Если что-то из этого не находишь на экране — пришли скриншот личного кабинета Turso, покажу точно куда жать.

### Как передать эти данные в Render

1. Зайди в свой Web Service на Render → **Environment**.
2. Добавь две переменные:
   - `TURSO_DATABASE_URL` = скопированный URL (`libsql://...`)
   - `TURSO_AUTH_TOKEN` = скопированный токен
3. Сохрани — Render автоматически передеплоит сервис с новыми настройками.

После этого при следующей пересборке данные останутся на месте.


**Можно ли открыть с телефона?**
Да, это просто веб-сайт — открывается в браузере телефона так же, как на компьютере.

**Данные точно останутся приватными?**
Сообщения лежат в твоей базе Turso, файлы — в Cloudinary, а push-уведомления идут через сервисы Google/Apple/Mozilla (содержимое шифруется). Это не end-to-end шифрование как в секретных чатах Telegram: администратор сервера технически может прочитать переписку. Для семейного чата это обычно нормально, но предупреди родных.

**Что если сервер выключится?**
PM2 (см. выше) автоматически перезапускает приложение при сбоях и после перезагрузки сервера.


## Безопасность

Что уже сделано в коде:
- Пароли хранятся только как bcrypt-хеши; секрет токенов обязателен (без него сервер не стартует).
- Регистрация только по коду приглашения (`INVITE_CODE`); лимит попыток входа (10 неудачных за 15 минут с одного IP).
- Ссылки на файлы принимаются только с твоего Cloudinary, весь пользовательский текст экранируется (защита от XSS).
- Заголовки безопасности (`helmet`, CSP), ограничение частоты запросов и загрузок.
- В группе удалять чат, чистить историю и выгонять людей может только создатель.
- Телефон, день рождения и «был в сети» видны только тем, у кого есть общий чат.

Чего нет: токен входа хранится в браузере (`localStorage`) 30 дней; сквозного шифрования нет; файлы в Cloudinary доступны по прямой ссылке.

Если репозиторий публичный — не клади в него `.env` и ключи. Если ключ когда-либо попадал в коммит, считай его утёкшим и выпусти новый.

## Premium, истории, приватность

**Premium** пока выдаёт администратор: профиль человека → «⭐ Выдать Premium» → эмодзи и срок в днях (пусто = без срока). Срок проверяется автоматически (раз в 10 минут), по окончании Premium отключается сам. Что он даёт:
- **Истории** на 24 часа (до 15 одновременно) и список тех, кто их посмотрел. Смотреть истории могут все, у кого есть общий чат с автором, кроме заблокированных.
- **Свой значок** (любое эмодзи) рядом с именем.
- **Файлы до 50 МБ** (бесплатно до 15 МБ).
- **Скрыть «был в сети»** (Настройки → Приватность).

Лента историй всегда на виду над списком чатов. Нажатие справа и слева листает, удержание ставит на паузу, свайп вниз закрывает, после последней истории человека сама открывается следующая.

**Блокировка людей.** В профиле собеседника → «🚫 Заблокировать». Заблокированный не может писать в личные чаты, звонить и находить тебя в поиске, и не видит твои истории. Список с кнопкой «Разблокировать» есть в Настройки → Заблокированные. В группы заблокированных не добавляют.

**Поиск людей.** Только по началу логина, от 3 символов, до 10 результатов, не больше 40 запросов в минуту. Не показываются заблокированные (в обе стороны) и забаненные. Настройки → Приватность → «Скрыть меня из поиска»: тогда человека находят только по точному логину.

**Смена логина** (Настройки → Логин, нужен пароль). Не чаще раза в 14 дней, старый логин 30 дней никто занять не может. Защита от подделки: похожие по написанию логины (кириллическая «а» и латинская «a», «l» и «1») считаются одинаковыми, а слова вроде `admin`, `support`, `mio` зарезервированы. Старые упоминания `@логин` в сообщениях не меняются.

**Администратор.** Права по `ADMIN_USERNAME` при запуске выдаются только если администратора в базе ещё нет, иначе после смены логина его старое имя мог бы занять кто-то другой. Чтобы передать права другому, выполни в консоли Turso: `UPDATE users SET is_admin = 1 WHERE username = 'логин';`

## Жалобы и модерация

**Для пользователей.** Долгое нажатие на чужое сообщение → «🚩 Пожаловаться». Или в профиле собеседника → «Пожаловаться на пользователя». Нужно выбрать причину (спам, оскорбления, запрещённый контент, мошенничество, другое). Администратор видит только то сообщение, на которое пожаловались (копию на момент жалобы, даже если автор потом его удалит), а не всю переписку. Ту же жалобу за сутки второй раз не создать, и не больше 10 жалоб в час.

**Для админа.** Админом становится аккаунт, логин которого указан в переменной `ADMIN_USERNAME` (при запуске сервера права выдаются автоматически). В шапке появляется кнопка 🛡, красный кружок на ней показывает число новых жалоб. В панели три вкладки:
- **Жалобы:** отклонить, закрыть без бана, удалить сообщение, бан на 7 дней, бан навсегда.
- **Люди:** поиск по логину, заблокировать или разблокировать.
- **Журнал:** кто, что и когда сделал (баны, разбаны, удаления).

**Бан.** Человека сразу выкидывает из приложения, войти он не сможет (увидит причину и срок). Временный бан снимается сам. Администратора заблокировать нельзя. Когда блокируешь человека по жалобе, остальные открытые жалобы на него закрываются вместе с ней.

**Чего пока нет:** автоматических фильтров спама и удаления файлов из Cloudinary (при удалении сообщения файл остаётся доступным по прямой ссылке). Если сервис станет публичным, за контент отвечает его владелец, а это ещё и юридический вопрос.

## Двухфакторная защита (2FA)

При входе после пароля нужен второй шаг. Включается в приложении: **Настройки → Безопасность**. Любое изменение защиты требует пароль.

Есть три способа. **Рекомендуется первый**: он работает в России без VPN, бесплатный и не зависит ни от каких внешних сервисов.

### 1. Приложение-аутентификатор (TOTP): настройка на сервере не нужна

Код из 6 цифр каждые 30 секунд считает приложение на телефоне, интернет для этого не нужен. Подойдут Яндекс Ключ, 2FAS, Aegis, Google Authenticator.

Как подключить: Настройки → Безопасность → «Подключить приложение» → введи пароль → добавь ключ в приложение (кнопка «Открыть в приложении» или ввод ключа вручную) → введи код из приложения → **сохрани 8 резервных кодов** (каждый работает один раз, показываются только сразу).

Секрет хранится в базе зашифрованным. Задай в Render переменную `TOTP_ENCRYPTION_KEY` (случайная строка, как для `JWT_SECRET`) **до того, как кто-то подключит приложение**, и больше никогда её не меняй. Иначе ключ берётся из `JWT_SECRET`, и смена `JWT_SECRET` сломает уже подключённые приложения.

### 2. Код на почту (Brevo)

На бесплатном Render обычная отправка почты (SMTP) заблокирована, поэтому используется HTTP-API.

1. Зарегистрируйся на [brevo.com](https://www.brevo.com) (бесплатно, 300 писем в день, карта не нужна).
2. Settings → **Senders, Domains & Dedicated IPs** → Senders → добавь свой адрес почты и подтверди его по ссылке из письма.
3. Settings → **API Keys** → создай ключ.
4. В Render добавь: `BREVO_API_KEY` = ключ, `MAIL_FROM` = подтверждённый адрес, `MAIL_FROM_NAME` = `Mío`.

Письма с кодом могут попадать в «Спам» — это нормально для адреса без собственного домена.

### 3. Код в Telegram (не рекомендуется для России)

В 2026 году Telegram в России ограничен, поэтому для семьи в РФ этот способ может не работать. Если не задать переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`, его в приложении просто не будет.

Если всё же нужен: создай бота у **@BotFather** (`/newbot`), добавь `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` (без `@`). Адрес сайта Render подставляет сам, иначе добавь `PUBLIC_URL`. В логах после деплоя должна появиться строка «Telegram-вебхук установлен».

### Если человек потерял телефон и резервные коды

Администратор может сбросить 2FA для него в консоли Turso (вкладка с SQL):

```sql
UPDATE users SET twofa_method = NULL, totp_enabled = 0, totp_secret = NULL, backup_codes = NULL WHERE username = 'имя_пользователя';
```

После этого человек входит по паролю и подключает защиту заново.
